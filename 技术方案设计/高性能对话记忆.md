# 赛博冰箱助手：高性能对话记忆技术方案 (Memory V1.0)

## 1. 核心架构
系统采用“双层存储 + 异步摘要”的架构模式，确保 Agent 既能快速响应，又不会产生“失忆”。

- **L1 缓存层 (Redis)**：
    - **滑动窗口 (Window)**：使用 Redis List 存储最近 N 轮对话原文。
    - **当前摘要 (Summary)**：使用 Redis String 存储当前会话的滚动摘要。
- **L2 持久化层 (MySQL)**：
    - 存储全量对话流水及最终状态，用于 Redis 过期后的“冷启动”恢复。

## 2. 核心流程

### 2.1 记忆提取流程 (Memory Retrieval)
1. **查询 Redis**：优先从 Redis 获取当前 Session 的 `Summary` 和 `Window`。
2. **缓存命中**：直接拼接 Prompt 发送给 LLM。
3. **缓存失效 (Cache Miss)**：
    - 从 MySQL 查询该 Session 最新的摘要和最近 N 条对话。
    - 将数据回填至 Redis，并设置过期时间（如 3 天）。

### 2.2 记忆存储与滚动流程 (Memory Rolling)
1. **实时保存**：每轮对话原文立即存入 Redis List。
2. **窗口检查**：当 List 长度超过预设阈值 $N$ 时。
3. **触发滚动摘要**：
    - 将被挤出的对话（最老的一条）与当前 Redis 中的 `Summary` 结合。
    - 调用小模型（如 Qwen-Turbo）进行异步合并生成新摘要。
    - 更新 Redis 里的 `Summary`，并清空被挤出的 List 节点。
4. **异步持久化**：通过 Spring `@Async` 或 RocketMQ 将新对话和新摘要同步至 MySQL。

## 3. 性能优化点
- **摘要异步化**：摘要生成不阻塞主对话流程，用户感知不到延迟。
- **Token 压缩**：无论对话多长，发给 LLM 的历史上下文始终控制在 `摘要 + N条原文` 的固定范围内。
