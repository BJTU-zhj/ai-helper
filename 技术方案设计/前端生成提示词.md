## 3. 后端与网关约定

后端服务是 `ai-kitchen-brain-service`，端口为 `8082`。

推荐通过网关访问：
- 网关基础地址：`http://localhost:8080/super-host`
- 网关会把 `/super-host/**` 转发到 `http://localhost:8082`，并 StripPrefix=1

直连后端备选：
- `http://localhost:8082`

前端统一从环境变量读取：

```env
VITE_API_BASE_URL=/super-host
```

开发期 Vite proxy 要配置：

```ts

  proxy: {
    "/super-host": {
      target: "http://localhost:8080",
      changeOrigin: true
    }
  }
}
```

不要配置或使用 `ai-utility-agent-service` 的 `/aihelper`、`/code-assistant` 等接口。

## 4. 后端接口契约

统一响应结构：

```ts
type CommonResp<T> = {
  success: boolean
  message?: string
  content: T
}
```

### 4.1 创建会话

```http
POST /brain/sessions
```

Body：

```json
{ "title": "可选标题" }
```

也允许不传 body。

响应：

```ts
CommonResp<SessionVO>
```

### 4.2 查询会话列表

```http
GET /brain/sessions
```

响应：

```ts
CommonResp<SessionVO[]>
```

### 4.3 查询会话详情

```http
GET /brain/sessions/{sessionId}
```

响应：

```ts
CommonResp<SessionDetailVO>
```

### 4.4 查询会话消息列表

```http
GET /brain/sessions/{sessionId}/messages
```

响应：

```ts
CommonResp<ChatMessageVO[]>
```

### 4.5 修改会话标题

```http
PUT /brain/sessions/{sessionId}/title
```

Body：

```json
{ "title": "新标题" }
```

响应：

```ts
CommonResp<SessionVO>
```

### 4.6 删除会话

```http
DELETE /brain/sessions/{sessionId}
```

响应：

```ts
CommonResp<boolean>
```

### 4.7 流式聊天，核心接口

必须使用这个接口：

```http
GET /brain/chat/stream/{sessionId}/{message}
Content-Type: text/event-stream
```

要求：
- `sessionId` 必须 `encodeURIComponent`
- `message` 必须 `encodeURIComponent`
- 不要使用 `/brain/chat/{sessionId}/{message}`
- 流式请求需要支持 `AbortController`，用于“停止生成”

数据结构：

```ts
type SessionVO = {
  id: string
  title: string
  createdAt: string
  updatedAt: string
}

type SessionDetailVO = {
  session: SessionVO
  messages: ChatMessageVO[]
}

type ChatMessageVO = {
  id: number
  sessionId: string
  turnNo: number
  role: "user" | "assistant" | string
  content: string
  createdAt: string
}
```

## 5. SSE 事件处理要求

后端 SSE 可能返回标准格式：

```text
event: answer_delta
data: {"message":"answer delta","timestamp":"...","delta":"文本片段"}
```

需要自己实现健壮的 SSE parser：
- 按 `\n\n` 拆分事件块
- 解析 `event:` 行
- 解析一个或多个 `data:` 行
- data 优先按 JSON 解析，失败时按纯文本处理
- 不认识的事件不要抛异常，只记录日志或忽略

可能事件名：

普通流：
- `start`
- `answer_delta`
- `done`
- `error`

ReAct 流：
- `start`
- `step_planned`
- `tool_started`
- `tool_finished`
- `step_failed`
- `degrade_started`
- `final_answer`
- `done`
- `error`

处理规则：
- `start`：进入流式状态
- `answer_delta`：读取 `data.delta`，实时追加到助手当前回答
- `final_answer`：读取 `data.finalAnswer`，作为最终回答；如果已经有增量内容，避免明显重复
- `step_planned`、`tool_started`、`tool_finished`、`step_failed`、`degrade_started`：可以在助手消息下方展示简洁的过程状态，不要喧宾夺主
- `done`：结束流、解锁输入框、刷新当前会话消息列表
- `error`：显示错误提示、结束流式状态
- 手动停止生成时显示“已停止生成”，不要显示成请求失败

## 6. 页面与交互要求

整体做成类似 DeepSeek 的聊天工作台。

布局：
- 左侧为会话栏
- 右侧为聊天主区域
- 移动端自适应，左侧会话栏可收起

左侧会话栏：
- 新建会话按钮
- 会话列表
- 当前会话高亮
- 显示会话标题和最近更新时间
- 支持重命名
- 支持删除，删除前二次确认
- 会话为空时显示简洁空状态

右侧聊天区：
- 顶部显示当前会话标题
- 中间为消息列表
- 底部为输入区
- 消息区分用户和助手
- 助手消息支持 Markdown
- 代码块需要有基本高亮
- 流式输出时内容稳定追加，不要闪烁重排
- 新消息生成时自动滚动到底部；如果用户主动上滑阅读，不要强制抢滚动

输入区：
- 多行输入框
- 发送按钮
- 流式中显示停止按钮
- Enter 发送，Shift + Enter 换行
- 空内容不可发送
- 没有当前会话时，发送前自动创建会话
- 请求中禁止重复发送

状态与错误：
- 网络错误、后端 `success=false`、HTTP 4xx/5xx、SSE 中断都要有明确提示
- 页面不要出现未捕获 Promise 异常
- 控制台不能有 Vue warning 或明显 runtime error

## 7. 视觉设计要求

使用 `frontend-design` skill 的标准执行。

设计方向：
- 高级、克制、干净，接近 DeepSeek 的聊天产品气质
- 不要廉价大渐变，不要花哨背景，不要紫色 AI 模板风
- 以浅色主题为主
- 可使用细腻边框、柔和阴影、明确层级、舒适留白
- 卡片圆角控制在 8px 左右，避免过度圆润
- 图标按钮要有 tooltip
- 按钮、输入框、消息气泡、会话项要有精致 hover/focus/active 状态
- 文本不能溢出或互相遮挡
- 移动端和桌面端都要可用

建议风格：
- 背景：接近白色或极浅灰
- 左侧栏：轻量分区、清晰列表
- 主聊天区：宽松阅读体验
- 用户消息：轻微强调
- 助手消息：更适合长文本阅读
