项目需求文档：赛博冰箱助手 (Cyber Fridge Assistant)
1. 项目愿景
   赛博冰箱助手是一个基于微服务架构的自主智能体（Agent）系统。它不仅是一个聊天机器人，而是一个能够理解食材风味逻辑、管理用户冰箱库存、并具备自主执行能力（如联网搜索、生成菜单报表）的“赛博大厨”。

2. 系统架构与服务定位
   系统采用双服务架构，通过意图路由实现“专业领域专家”与“通用杂务处理”的解耦。

2.1 ai-kitchen-brain-service (核心大脑 / 赛博大厨)
定位：系统的主入口，专注于“饮食与食材管理”领域的深度专家。

核心功能：

意图拦截与路由：识别用户输入。若是饮食相关，由本地 Agent 处理；若非相关领域，则将请求转发至 ai-code-assistant-service。

食材推理（RAG）：基于底层风味公式和食材搭配逻辑，为用户提供“发明菜品”服务，而非机械检索菜谱。

自主执行（Manus-style）：能够通过工具调用完成闭环任务。

技术栈：Spring AI, Redis, mysql, MCP,skill，rocketMQ等。

2.2 ai-utility-agent-service (通用执行器 / 杂务处理)
定位：无状态的通用助手。

核心功能：

通用问答：处理非饮食领域的日常问题。

实时工具查询：如天气预报、汇率转换、简单代码片段编写等。

技术栈：LangChain4j,mcp等。

3. 关键技术实现要求
   3.1 高性能对话记忆 (Memory)
   要求：在 ai-super-host 中接入 Redis 存储。

目标：实现跨 Session 的长期记忆。Agent 需记得用户的忌口（如不吃香菜）、冰箱现有食材、以及历史推荐偏好。

3.2 领域 RAG (检索增强生成)
知识库内容：轻量级 Markdown 文档，包含：

《底层风味搭配公式》（如：蛋白质+酸度+油脂平衡原则）。

《食材保存与处理指南》（如：空气炸锅时间表）。

技术点：文本切块优化、向量召回精度调优。

3.3 MCP (Model Context Protocol) 挂载
要求：使 Agent 具备操作本地环境的能力。


3.4 扩展 Skill (技能包)
联网搜索：集成 Tavily 或 Google Search API，获取实时物价或流行做法。

PDF 生成：集成 PDF 库，根据用户满意的食谱或周计划，自主生成排版精美的 PDF 菜单。

4. 业务流转示例
   用户输入：“我冰箱里有剩的西红柿和鸡蛋，帮我出个主意，顺便打印成 PDF。”

ai-super-host：

识别为“饮食领域”。

查阅 RAG 知识库中的“剩菜处理归宿”。

结合 Redis 记忆（用户喜欢重口味）。

调用 PDF 生成 Tool。

返回结果并通知 PDF 已保存至本地。

用户输入：“明天下雨吗？”

ai-super-host：识别为“非核心领域”，透传至 ai-code-assistant-service 获取天气并返回。
